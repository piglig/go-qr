# Styling

*Since v2.2.*

![Six QR Code styles](../images/styles.png)

Styles are rendering options, so they work with `PNG`, `SVG` and `Image`:

```go
navy := color.RGBA{R: 0x1a, G: 0x23, B: 0x7e, A: 0xff}
teal := color.RGBA{G: 0x69, B: 0x5c, A: 0xff}
png, err := code.PNG(
	qr.WithModuleShape(qr.ModuleRounded),
	qr.WithFinderShape(qr.FinderRounded),
	qr.WithGradient(navy, teal, 45),
)
```

The images above are generated by
[`docs/styles_gen.go`](../styles_gen.go), which checks every style with
`Verify` before drawing it.

## Options

| Option | Values |
| --- | --- |
| `WithModuleShape(s)` | `ModuleSquare` (default); `ModuleDot`, circles 0.8 modules across; `ModuleRounded`, which rounds every corner whose neighbors are light, so runs of modules merge into smooth shapes and lone modules become circles. |
| `WithFinderShape(s)` | `FinderSquare` (default), `FinderRounded`, `FinderCircle`. |
| `WithFinderColor(ring, center)` | Colors of the three finder patterns' rings and centers. |
| `WithGradient(from, to, angle)` | Linear gradient over the dark modules, replacing the foreground. `angle` is in degrees: 0 runs left to right, 90 top to bottom. Finders follow the gradient unless `WithFinderColor` is given. |

Text output ignores styles.

## Keeping styled codes readable

Readers find a QR Code by its finder patterns, which read 1:1:3:1:1 along
any line through their centers, and then sample the center of each module.
Every style keeps both: module centers keep their color, and rounded and
circular finders keep the 1:1:3:1:1 proportions through the center.

Styles still remove some of the margin readers have for blur and distance,
so:

- **Verify the exact options** before publishing. `Verify` decodes the
  rendering and checks the contrast of every dark color in use, including
  both ends of a gradient and the finder colors.
- **Keep every dark color dark.** A gradient that fades toward the
  background color fails where it is lightest.
- **Prefer higher error correction** (`WithECC(qr.ECCQuartile)` or
  `ECCHigh`) for dot modules, which cover less of each module.
- **Use enough pixels.** Anti-aliased dots need about three pixels per
  module to sample cleanly.

Some decoders have a "pure barcode" mode for perfectly aligned images that
assumes square finders; it rejects rounded and circular finders. Normal
camera scanning reads them.

## Output and performance

- **SVG** draws modules and finders as paths, and gradients as an SVG
  `<linearGradient>` whose id is derived from its colors and angle, so
  several codes inlined in one HTML page do not interfere.
- **PNG** with shapes in two colors is an 8-bit paletted image, about 2.7× the
  cost of a plain PNG. Gradients and finder colors need an RGBA PNG, about 10×
  the cost, mostly compression.
- For many styled codes, SVG is the fast choice.
